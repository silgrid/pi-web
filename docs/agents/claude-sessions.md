# claude sessions

pi-web can run a session on the **claude** harness instead of pi: a `claude -p` child process per live session, translated into pi-web's existing session events. pi sessions are untouched; everything below applies only to rows whose `harness` is `"claude"`.

Files: `lib/claude-shared.ts`, `lib/claude-argv.ts`, `lib/claude-config-dir.ts`, `lib/claude-index.ts`, `lib/claude-adapter.ts`, `lib/claude-session.ts`, `app/api/claude/route.ts`, the claude branches of `app/api/agent/**` and `app/api/sessions/**`, `instrumentation-node.ts`, the claude parts of `hooks/useAgentSession.ts`, `components/ChatInput.tsx` (`ClaudeComposerControls`), `components/ChatWindow.tsx`, `components/SessionSidebar.tsx` (`HarnessMarker`), `components/AppShell.tsx`, `components/SettingsPanel.tsx` (`ClaudeConfigDirSection`), `claude.*` in `lib/i18n/messages/*`.

## Choosing the harness
- A fresh composer offers **pi** (the default, unchanged) or **claude** (`ClaudeComposerControls`). claude also takes a model alias from the fixed set `sonnet` / `opus` / `haiku` / claude-default and a tool preset, `read-only` (default) or `writable`. Harness, alias and preset are fixed for the session's life: an open claude session shows them as one line ("claude · sonnet · read-only — fixed for this session") and offers no model, reasoning, tool-preset or compact control.
- `POST /api/agent/new` takes `harness: "claude"`, `modelAlias` (required) and `claudePreset` (default `read-only`) with type `prompt` or `ensure_session`. The order is the guard's: validate the fields, `isRegistrableRoot(cwd)` (the pi route's refusal and reason), claude on `PATH`, then the index entry, the config dir and the first child. Nothing is created before the guard passes. claude-default passes no `--model`; the others pass exactly the alias.
- `claude` is resolved from `PATH` only, on every call (`findClaudeBinary()`); there is no path setting and nothing bundled. `GET /api/claude` reports `{ available, reason?, configDir, modelAliases, presets, defaultPreset }` without creating anything; when claude is missing, the composer's claude option is disabled and says so in visible text.

## Preset → flags (`lib/claude-argv.ts`)
Every child: `-p --input-format stream-json --output-format stream-json --verbose --include-partial-messages`, plus `--session-id <id>` on the first launch or `--resume <id>` once claude has a transcript for the id.

| preset | flags | effect |
|---|---|---|
| read-only | `--bare --strict-mcp-config --disable-slash-commands --permission-mode dontAsk --permission-prompts none --tools Read,Glob,Grep --allowedTools Read,Glob,Grep` | no Bash, Edit, Write, web tools or Agent; anything that would prompt is denied. Bare mode skips hooks, plugins and **the session cwd's `CLAUDE.md`**; strict MCP loads no server. The config dir still contributes env, model settings and deny rules. |
| writable | `--permission-mode acceptEdits --permission-prompts none --tools Read,Glob,Grep,Edit,Write,Bash --allowedTools Read,Glob,Grep,Edit,Write` | edits are accepted; Bash runs only what the config dir's `permissions.allow` pre-approves, everything else is denied automatically (plain file commands such as `touch` in the cwd are accepted by `acceptEdits` itself). No bare mode: the config dir's MCP servers, hooks, plugins and allow/deny rules apply, and claude **loads the session cwd's `CLAUDE.md`** — known, accepted behaviour, stated in the UI, never a toggle. |

Observed with claude 2.1.312 (fixture README): under `--bare` only `Read` of `Read,Glob,Grep` is offered. Owner ruling ( review round 1): read-only means Read only; the argv stays as specified and keeps `--bare` (no cwd `CLAUDE.md`). With no write tool offered a read-only write is never attempted, so its proof is the file staying absent (`read-only-deny.jsonl`, empty `permission_denials`); the denial-as-tool-error proof is the writable Bash allow-list recording (`writable-bash-deny.jsonl`).

## Config dir and credentials (`lib/claude-config-dir.ts`)
- Every child runs with `CLAUDE_CONFIG_DIR=<pi agent dir>/claude` (`PI_CODING_AGENT_DIR` moves it), never `~/.claude` or the daemon's. The first claude session creates it (0700) with a `settings.json` of `{}` (0600, atomic); an existing file keeps every byte.
- The child's env is pi-web's minus `PI_WEB_PASSWORD`, every `ANTHROPIC_*`, every `CLAUDE_*` and `CLAUDECODE`, plus `CLAUDE_CONFIG_DIR` (`buildClaudeEnv()`). Credentials belong in that `settings.json`'s `env`; pi-web never reads, logs or displays them. A failed turn (an authentication error, a child that exits) shows claude's own text plus `(claude config dir: <path>)` as an error notice.
- Settings › General shows the path read-only with each preset's wording (`ClaudeConfigDirSection`).

## Index, list and history
- pi-web keeps its own index, `<pi agent dir>/claude-sessions.json` (`lib/claude-index.ts`): `{ id, cwd, name?, modelAlias, preset, created, modified, firstMessage, usage, archived? }`, written whole per change (serialized per file, temp + rename), each write bumping the session list version. A missing or corrupt file reads as empty. The claude session id is pi-web's id.
- `GET /api/sessions` adds those rows (`harness: "claude"`, `claude: { modelAlias, preset }`, `archived`) beside the pi rows; nothing scans claude's projects directory, so a claude session created outside pi-web is never listed, and nothing is written to the pi sessions store.
- History is claude's own transcript, `<config dir>/projects/*/<id>.jsonl`, found by id and read through the adapter (`GET /api/sessions/[id]`): no parallel event log exists. The detail has no branch tree; `snapshotRevision` is null (the transcript grows behind pi-web).
- `PATCH /api/sessions/[id]` takes `{ name }` and `{ archived }` for claude rows (index only); the sidebar's archive set mirrors the index for claude rows and keeps the browser set for pi rows. `DELETE` ends the child, then removes that session's transcript and index entry, nothing else.
- Usage is the sum of each turn's `result` aggregate (input, output, cache read/write, cost), recorded in the index and served by `GET /api/sessions/[id]` `stats`, `POST /api/sessions/stats` and `get_session_stats` — never the streamed per-message usage, which under-counts.

## Lifecycle (`lib/claude-session.ts`)
- One `ClaudeSession` per live child in a `globalThis` registry. It implements the event-stream session shape, so `GET /api/agent/[id]/events` hands it to `createAgentEventStream()` unchanged; opening the stream starts a child when none is alive.
- The child lives while a page renews the lease (`POST /api/agent/[id]/lease` renews, never spawns) or a turn runs, and ends one `PI_WEB_IDLE_TIMEOUT_MS` after the last renewal (`0` disables). It runs in its own process group (`detached`), which is what shutdown signals: stdin closed, SIGTERM, SIGKILL after 3 s; any descendant left after the leader exits is killed too. `instrumentation-node.ts` ends every group on SIGINT/SIGTERM.
- The next open or send after an exit starts `claude --resume <id>`: the same conversation, its history read from the transcript.
- Commands answered for a claude id: `prompt` (one turn at a time: no queue, no steer; the composer keeps Send disabled with a visible reason while a turn runs), `abort`, `get_state`, `get_tools`, `get_commands`, `get_session_stats`. Every other command is refused (400, "not available for claude sessions") and starts nothing.
- Stop writes the stream-json interrupt control request; a turn still running after 5 s gets SIGINT on the process group. The partly streamed reply stays as a final message, the turn ends `aborted` (no error notice), and the session takes the next message.
- A turn's end emits `agent_end`, `agent_settled`, `prompt_done` (the running indicator, completion sound and notification follow them as for pi) and records the `result` usage.

## The adapter (`lib/claude-adapter.ts`)
The only module that knows claude's formats. `ClaudeStreamTranslator` maps stream-json events to pi events: `stream_event` content blocks → `message_start` / `message_update` (`text_*`, `thinking_*`, `toolcall_*`), each `assistant` event → the authoritative `message_end` (one per content block, as claude emits them; empty redacted thinking dropped) and `tool_execution_start` for its tool calls, `user` tool_result blocks → `tool_execution_end` + a `toolResult` message (`isError` from the block: an auto-denied action is an error result naming the denial), `result` → `agent_end` plus the turn's usage or claude's error. `claudeTranscriptToMessages()` maps the jsonl transcript to the same messages, entry ids from each entry's `uuid`. Contract tests run on real recordings, `lib/__fixtures__/claude-2.1.312/` (provenance and scrubbing in its README).

## Unsupported pi features
Hidden for claude sessions: fork, edit-from-here, ask-in-new-chat, branch navigation (no tree), compaction and its recovery, model / reasoning / tool changes, steer and follow-up, built-in slash commands (`/mcp` included), attachments, background tasks, the subagent switcher, title generation. HTML export is disabled with visible text in the toolbar. No permission approve/deny control exists: `--permission-prompts none` denies, and the denial shows as a tool error. A claude turn renders like a pi turn: once answered, its process details (intermediate text, tool calls and results) fold behind the turn's toggle.
